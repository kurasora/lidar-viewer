# F5 画面の動き 修正記録

確かめ方: 写し（$T/work/F5/proj）を build して Chromium で `t1.js`（主な再現手順）・`t3.js`（試作ページ）・`t4.mjs`（軌跡の判定）・`browser_read.js`（サンプル 3 つ）。

## 直したもの
- B24: 順番待ちがある間は updateBounds・applyColor（全ファイル分）を最後の 1 回にまとめる（S.refreshPending → finishBatch）。「すべて閉じる」ボタン（removeFile/afterRemove で 1 回だけ計算）。40 個×2 万点: 開く 9〜14 秒（1 個あたりほぼ一定）、すべて閉じる 15 ms。
- B27: worker.onerror を追加（試作ページの代理にも）。確保失敗などの英語の誤りを「メモリが足りません。『表示』の『読み込む最大点数』を減らして…」に言い換え（jaError）。失敗したら別スレッドに remove を送って残った点群を消し、順番待ちを先へ（loadFailed）。onLoaded/onTraj の中で例外が出ても次へ進む。
- B30: 閉じたあと、残りに「値」の項目も RGB もなければ黙って高さに戻す（afterRemove）。確認: 知らせ空。
- B33: Ctrl/Alt/⌘ 付き・変換中・入力欄の中ではショートカットを動かさない。確認: Ctrl+C で hideCeil 変わらず。
- B34: Delete/Backspace は「距離」が入っているときだけ。消したら「n 番目の距離を消しました」。確認: 切っている間は残る。
- B52: 知らせは折り返して全文（4 行、誤りは 8 行まで）。誤りにファイル名を入れ、続く「開きました」で上書きしない（status の soft）。まとめて開いたら最後に「n 個のうち m 個を開けませんでした（名前）」、理由は「開く」カードの #loadErrors に残す。確認済み。
- B53（画面側）: isTrajectory を名前で決めず中身で判定（見出しに qx〜qw / orientation.x〜w、または「t x y z」見出し＋時刻が増える 4/8 列、または見出しなしで 8 列以上・時刻が増える・四元数の長さ 1±0.05。12 列は KITTI として除外。F1 の parseText の受け付けに合わせた）。一覧の .txt/.csv に「軌跡として開き直す／点群として開き直す」。確認: CloudCompare の timestamp 見出し・Original_cloud_index・Livox CSV・名前に odom → 点群、相対時刻の TUM・サンプルの trajectory.txt → 軌跡。
- B57: 間引きをホイール・視点のアニメーション・中心の印のドラッグの間も効かせる（最後に動いてから 220 ms は間引いたまま。bumpInteract）。並べ替えなど進み具合の分からない段階は帯を動かし続け「（しばらくかかります）」。確認: ホイール直後は間引き、0.8 秒後に全点。
- B63: 止まる原因は onLoaded の中の例外（地図＋UTM で範囲・天井の計算が落ちる）で loadNext が呼ばれないこと → B27 の try/catch で順番待ちは止まらない（試作ページで地図のあと .las → .shp 点が 1.7 秒で開く）。「画像を保存」は試作ページでは画像を大きく出し「右クリックで保存」と案内（#shotView、Esc・× で閉じる）。
- B74: `#info .muted` の見た目（注記の文言そのものは F2 の担当）。
- B77: fmt で -0.00 → 0.00（STEP の mm は F2）。
- B79: ファイルの色は使っていない色から選ぶ。軌跡は 2 本目から別の色（TRAJ_COLORS）、一覧で色を変えられる。
- B80: 保存名 lidar_…png。「保存しました」と言わず「保存先を選んでください」。data: ではなく blob: で渡す。
- B81: Esc は入力部品にフォーカスがあっても効く。カードを出したら見出し（tabindex=-1）へ、閉じたら下のカードかドックのボタンへフォーカスを戻す。
- B82: index.html に color-scheme と背景色のインライン指定。カードが開いているときは空の画面の案内・操作の案内をカードの右側に寄せる（:has）。操作の案内は語の途中で折れないよう区切り単位で nowrap。ラベル列 84→112px・keep-all。凡例の長い名前は折り返す。
- B84: 「ファイル」カード→「開く」、中の欄→「開いているファイル」。ドック「補正」→「水平補正」。空の画面と操作の案内の言い方をそろえた。半角かっこ→全角。矢印・中心の印の軸名を小文字 x y z に。表の高さの差 3 桁、軌跡の時間 1 桁。背景の明るさを %。SBF の種類名を日本語に。「単色表示のときの色」→「1 色のときの色」。サンプルの説明「前回の廊下の地図」→「廊下の地図と軌跡」。
- B85: 軌跡の始点・終点を丸に。天井がないときは「天井を隠す」を入にせず押せない見た目（.na）、押すと「この点群には天井が見つかりません」。
- B86: 右上の文字に下地。選ばれた切り替えに下線、選択中のファイル行に左の帯、配色の選択は枠（フォーカスの輪と別）、溝の縁を明るく。強制カラー用の @media。
- B87: 2 つつまみは自由にすれ違える（小さい方が下限）＋最後に触った丸を上に。確認: 左端で重ねたあと右へ動かせる。
- B88: devicePixelRatio の変化を matchMedia で拾って setPixelRatio・resize。
- B91: 点群がないときは軌跡の範囲で視点を合わせる（開いたときと「全体」）。確認: 原点から離れた軌跡に合う。

## 直さなかったもの・ほかの担当へ
- F6: 起動直後の白い光りの本体は main.js の BrowserWindow に `backgroundColor: '#0e1317'`（または show:false＋ready-to-show）が必要。保存の画面の題名・保存できたかの知らせは main.js の `will-download`（setSaveDialogOptions({title:'画像を保存'})、done で completed のときだけ画面へ）が必要。render-process-gone の扱いも F6。
- F3: ライブの「この PC に…」（→パソコン）、デモの説明「前回の廊下の地図から作る」・ファイルなしの知らせ。
- F4: applyColor の「…単色で表示しています」（→1 色）、座標の吹き出しの軸名が大文字 X Y Z（こちらは小文字にした）、色の範囲に単位がない。地図（シフト 0）のあとに UTM を開くと S.offset=[0,0,0] のまま使われ精度が落ちる件（読み込みの offset の扱い、F1 と相談）。
- 測っていた変数 liveBusy が F3 の関数名とぶつかったので、計測側を mBusy/mNext に改名した。
- B53 の「軌跡として読めないものを断る」部分は F1（trajectory.js）。
