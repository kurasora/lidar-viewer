# F3 ライブ 修正記録

試験: netns f3（10.133.0.1〜4）でにせ LiDAR 2 台・ロボット役（SDK2 と同じく送り先を自分に設定）・Node の Live（$T/work/F3/run.sh, app.js）と Electron の画面（runui.sh, ui.js）。

| ID | 直したこと | 確かめ |
|---|---|---|
| B17 | つなぐ前に 0x0101 で 0x0006/0x001a/0x0000 を問い合わせ、ほかの PC 宛てなら `TAKEOVER:<ip>` を返し、カードに「○○ に送っている点群をこのパソコンに切り替えます。止めると元に戻します」＋切り替える/やめる。止める・別の LiDAR・終了（main.js の will-quit で最大 2 秒待つ）で元の送り先・形式・動作モードへ戻す。元がほかの PC でなければ待機（IDLE）にして送信を止める。にせ LiDAR に 0x0101 の返事と動作モード（待機中は送らない）を追加 | ロボットの受信 2000→0→（止める）2000、アプリ終了でも戻る。B→A の切り替えで B は待機 |
| B18 | LiDAR 用の 4 つの受け口から reuseAddr を外し、EADDRINUSE/EACCES は「ポート N がほかのソフト…」 | reuseAddr のドライバが 56301 を持つと errors に出る。放すと開ける |
| B22 | 表示して 4 秒点が来ない（または途切れた）とき、カードに案内（Windows はファイアウォールの許可の手順、ほかは ufw、共通で livox_ros_driver2） | iptables で 56301 を落として案内が出る |
| B28 | 点群の箱: 版 0・長さ欄＝実長・36+点数×大きさ＝実長を確かめる。検出の返事は中身の IP と送り元が同じものだけ、設定の返事は待っている命令・通し番号・LiDAR の IP が合うものだけ | でたらめな箱 20 個 → bad 20、点にならない |
| B51 | 警告は戻り値 `warn` にしてカード内に残し赤で出す／待つ間「つないでいます…」で表示ボタンを無効／世代番号で古い操作は CANCELLED（画面は無視）／カードを閉じて表示もしていなければ 12 秒でポートを放す（画面がカードを開いている間 4 秒ごとに open）／NIC ごとの IP に bind したソケットからも 255.255.255.255 へ探す・見つからないときに 192.168.1.50 の案内 | 競合で CANCELLED・mode null。止めて放置でポートが閉じ、開き直しで戻る |
| B83 | `.livesec button:disabled` の見た目、「見ている人: n 台」を配信中だけ別の行に、ライブ中は右上を「ライブ n 点/秒（いま m 点）」、止めたら戻す | 画面で確認 |
| B92 | Sharer の待ちを stop() で CANCELLED にして setShare は sharing:false を返す。画面はチェックを主プロセスの状態に合わせる | listen 直後に止めても返る（sharing=false） |
| A11-019 | `liveHides(f)` を作り、pickAt の 1 行で隠れた地図を除く | デモ中/LiDAR 中に pickAt → null |

直さなかったもの: 点群の箱の CRC32（本物の計算範囲を実機で確かめていないため数えるだけにもしていない）、配信の知らせのなりすまし（A08-005。IP は一覧に出ている）、マルチキャストでの共有（案のみ）。

実機で確かめること:
- 本物の MID-360 が 0x0101 に返事し、0x0006 の値（送り先）が livox_ros_driver2 の host_ip と一致するか。戻したあとロボットの FAST-LIO に点群が戻るか
- 待機（0x02）にしたあと、ロボット側のドライバが再接続時に動作モードを戻すか
- 検出: NIC の IP に bind したソケットからの 255.255.255.255 で、別サブネット・既定の経路なしの LiDAR が見つかるか（返事がどのポートに来るか）
- Windows: reuseAddr なしでも SDK2（SO_REUSEADDR）があとから来ると取り合いになるか。そのとき B22 の案内が出るか。ファイアウォールの手順の文言が実際の画面と合うか
