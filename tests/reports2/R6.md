## 見つけた問題

### R6-001 [重大] 軌跡だけを開いて閉じると、そのシフトが残り、次に開くローカルの点群が 25 cm 刻みに丸められる（F4 B11 × F5 afterRemove）
- 再現: 「軌跡を開く」で UTM の軌跡（traj_utm.txt、539000/3836000）だけを開く → 一覧の × で閉じる → ローカルの local.pcd（0〜10 m、0.1 mm 単位）を「開く」
- 期待: 何も開いていないのでシフトなし（[0,0,0]）、座標はそのまま
- 実際: S.offset = [539000, 3836000, 0] のまま使われ、y が 0.25 m・x が 0.0625 m 刻みになる（5,000 点で y の値が 25 種類だけ、例 1.8812→2、2.79→2.75）。ほかに何も開いていないのに、注記は「先に開いたファイルと原点が約 3,875 km 離れています」と出る
- 場所: app.js:944（B11 で軌跡が S.offset を決めるようにした）、app.js:1033-1037 removeTraj（何も残らなくても S.offset を戻さない）。S.offset を戻すのは afterRemove（app.js:1022）だけで、それは点群を閉じたときにしか呼ばれない。「すべて閉じる」（2 つ以上のとき）なら戻る
- 直し方の案: S.offset を戻す処理を「点群も軌跡もなくなったとき」に 1 か所にまとめ、removeTraj からも呼ぶ
- 確度: 再現済み（$W/b1.js の 1a〜1c）

### R6-002 [中] 地図座標の地図と軌跡を開いて地図だけ閉じると、軌跡が元の座標を失い、次の点群と食い違う（R6-001 の裏側）
- 再現: utm.xyz を開く → traj_utm.txt を「軌跡を開く」で開く → 地図の × → local.pcd を開く
- 期待: 軌跡は地図座標（539000…）のまま。次の点群と原点が違うなら知らせる
- 実際: 地図を閉じた時点で S.offset = null（軌跡はシフトを引いた値 (0.004, 0.001, 29.99) のまま）。local.pcd で S.offset = [0,0,0] になり、軌跡がローカルの点群の上（原点付近）に重なって出る。知らせなし。「軌跡に沿って動かす」・軌跡の座標もずれる。同じ形で、別の UTM 地図を開くと中央値の丸め（100 m）の差だけずれる
- 場所: app.js:1022（afterRemove が軌跡が残っていても S.offset を null にする）、app.js:945（軌跡はそのときの S.offset を引いて持つだけで、自分のシフトを覚えていない）
- 直し方の案: 軌跡が残っている間は S.offset を消さない。または軌跡ごとに引いたシフトを持ち、S.offset が変わったら差を足して作り直す
- 確度: 再現済み（$W/b1.js の 2a〜2c）

### R6-003 [軽微] 「time,x,y,z,…」見出しの 8 列の点群 CSV をドラッグ（OS から開く）と、軌跡と判定されて開けない（F5 isTrajectory × F1 parseText）
- 再現: 見出し `time,x,y,z,intensity,red,green,blue`、時刻が増える 5,000 行の CSV を窓にドラッグ
- 期待: 点群として開く（または軌跡として開いて「点群として開き直す」が出る）
- 実際: 赤で「5〜8 列目が姿勢（四元数）になっていないため、軌跡として読めません（FAST-LIO の pos_log など…）」。一覧に入らないので「点群として開き直す」も押せない（「開く」ボタンからなら点群で開ける）。4 列の `timestamp,x,y,z`（時刻順に並んだ点群）は軌跡として開く（こちらは開き直しで戻せる）
- 場所: app.js:686（見出しの道は 8 列のとき四元数を確かめない）、trajectory.js:129 で断る。見出しなしの道（app.js:690-691）は四元数を確かめるので食い違っている
- 直し方の案: app.js:686 でも 8 列なら 5〜8 列目の長さ 1 を確かめる。軌跡として読めなかった自動判定のファイルは点群で開き直す
- 確度: 再現済み（$W/b1.js の 3）

### R6-004 [軽微] ライブ中に視点を動かすと、右上の「ライブ n 点/秒」が隠したファイルの点数（ファイルがなければ「点群なし」）に戻る（F3 × F5 B57・F4 B89）
- 再現: local.pcd を開く → デモを表示 → ホイールを回す
- 期待: ライブの間は「ライブ … 点/秒（いま … 点）」のまま
- 実際: 直後〜0.45 秒後も「表示 20,000 点 ／ 全 20,000 点」（隠している地図の数）。次の 1 秒ごとの更新まで戻らない。視点を動かし続けるとずっと地図の数が出る。切り出し・天井（updateClip）でも同じ
- 場所: app.js:268 bumpInteract → applyLod（app.js:283）→ updateStatus（app.js:1909）が LV.src を見ない。ライブの文は app.js:2223（1 秒ごと）だけ
- 直し方の案: updateStatus の先頭で LV.src なら updateLiveNow の文を出す
- 確度: 再現済み（$W/b2.js の B）

### R6-005 [軽微] ライブのカードの一覧が 4 秒ごと（表示中は 1 秒ごと）に作り直され、キーボードのフォーカスが body に落ちる（F3 の keepalive × F5 B81）
- 再現: にせの pcdLive（LiDAR 2 台）でライブのカードを開く → Tab で 2 台目の「表示」にフォーカス → 5 秒待つ
- 期待: フォーカスはその「表示」に残る
- 実際: document.activeElement = BODY。Enter で表示できない。マウスでも押している間に作り直されるとクリックが落ちることがある（推定）
- 場所: app.js:2246（4 秒ごとの open → renderLiveLists の innerHTML 作り直し、0.4.0 で追加）、app.js:2232（表示中は live.js:421 の毎秒の state でも作り直す）
- 直し方の案: 一覧の中身（SN・IP・busy）が変わったときだけ作り直す。作り直すときはフォーカスのある data-lsn/data-lpeer を覚えて戻す
- 確度: 再現済み（$W/b2.js の A。主プロセスはにせ物）

### R6-006 [軽微] 配信につないでいる途中で止める・ほかを表示すると、古い接続の英語の誤りが知らせに出る
- 再現: 握手に答えない相手へ startPeer → 0.3 秒後に stopAll（Node で Live を直接）
- 期待: 止めた接続の誤りは出さない
- 実際: log「配信につながりません（WebSocket was closed before the connection was established）」が出る（画面では右上に出て「LiDAR につないでいます…」などを上書き。英語が混ざる＝B16 の方針と食い違い）
- 場所: live.js:500（error の受け手が `this.ws !== ws` を見ない。close の受け手 live.js:494 は見ている）
- 確度: 再現済み（$W/n1.js）

### R6-007 [軽微] ライブ中にファイルの表示を切ると、止めたあとにチェックは外れたまま点群が出る（0.3.x からある）
- 再現: local.pcd → デモ → 一覧のチェックを外す → 止める
- 実際: f.visible=false・チェックなしなのに points.visible=true（描かれるが pickAt・範囲・LOD では見えないもの扱い）。逆にライブ中にチェックを入れると地図がライブに重なる
- 場所: app.js:2253・2261（LV.hidden を f.visible と別に持って戻す）、app.js:1045
- 確度: 再現済み（$W/b2.js の C）

### R6-008 [情報] 死にコード・名前の食い違い（コード上）
- worker が誤りに付ける `unsure`（worker.js:372・603）は、call()（app.js:57）が `new Error(m.message)` にするので画面に届かない。runLevel は auto かどうかだけで分けており、unsure は使われていない

- window.__pcd.updateLive は「距離の線の追従」（app.js:1583）で、ライブの updateLiveNow（app.js:2202）と名前が紛らわしい（F5 が liveBusy→mBusy に改名したのと同じ理由）
