## 見つけた問題

### R1-001 [重大] ライブのカードを開いたあと、表示していないときに Cmd+Q・Ctrl+C（SIGINT）・SIGTERM で終わると、窓のないままプロセスが残る
- 再現: カードを開く（LiDAR 一覧が出る）→ 何も表示せずに `app.quit()`（mac の Cmd+Q と同じ）／ SIGINT／SIGTERM。比べ: ライブ未使用・窓を閉じる・表示中に quit はすぐ終わる
- 期待: 終わる / 実際: 10 秒たっても残る（窓 0 枚）。b・e・f の 3 通りとも再現
- 影響（推定）: 二重起動の鍵を持ったままなので、もう一度起動しても即終了して何も出ない。mac の Dock に残り続ける
- 場所: main.js:27（will-quit）。原因の見立て: 戻すものがないと `live.close()` がマイクロタスクのうちに終わり、will-quit を出している最中に `app.quit()` が呼ばれて無視され、そのあと preventDefault で終了が取り消される
- 直し方の案: `.then(() => setImmediate(() => app.quit()))` か `app.exit()`。または戻すものがないとき（`live.lidar.active` なし）は preventDefault しない
- 確度: 再現済み（ud を分けた Electron 34.5.8・Linux）／ 再現: regress/s6.sh（ui3.js b e f）

### R1-002 [重大] 2 台の LiDAR Viewer が順に同じ LiDAR を切り替えると、ロボットに点群が二度と戻らない（A を止めると B の表示も切れる）
- 再現: ロボット（.2）が X を使用中 → A が確認して切り替え（元 = .2）→ B が確認して切り替え（元 = A の .3）→ A が止める → B が止める
- 期待: 最後にロボットへ戻る。A の「止める」で B の表示を止めない
- 実際: A が止めた時点で X の送り先が .2 に戻り、B は点が来なくなる（4 秒後に「ファイアウォール…」の的外れな案内）。B が止めると送り先が .3（もう見ていない A）になり、ロボットの受信は 0 のまま（robot.log: 19 秒以降 X=0）
- 場所: live.js:231-246（stop が、いまの送り先が自分かを確かめずに戻す）
- 直し方の案: 戻す前に 0x0101 で 0x0006 を読み、自分宛てのときだけ戻す。横取りした先が LiDAR Viewer（配信の知らせの IP）なら、その PC の「元」を引き継ぐ（または「元は LiDAR Viewer」と画面に出して確認する）
- 確度: 再現済み ／ 再現: regress/s1.sh

### R1-003 [重大] 0x0101 に答えない LiDAR（古いファームウェア・返事が 1 秒失われた）では、確認なしで横取りし、止めると待機にしてロボットへの点群を止める
- 再現: 0x0101 だけ答えない にせ LiDAR Y（`OLDFW=1`）をロボットが使用中 → A で「表示」→ 止める
- 期待: 元の送り先が分からないことを知らせ、確かめてから切り替える。止めたら元に戻す（少なくとも待機にはしない）
- 実際: 確認なしで表示（warn null・画面に注意なし）。止めると Y は「動作モード: 待機」、ロボットの受信は 0 のまま
- 場所: live.js:206-217（q が null → orig null → other=false）、:242（元がほかの PC でなければ IDLE）。`origUnknown` を返しているが app.js は使っていない
- 直し方の案: q が null のときも確認を出す（「送り先を確かめられませんでした」）。止めるときは元が分からなければ待機にせず送り先も変えない。問い合わせの試行を増やす
- 確度: 再現済み ／ 再現: regress/s1.sh

### R1-004 [中] 止めるときに LiDAR が返事をしないと、赤の「戻せませんでした」をすぐ「送り先を 10.141.0.2 に戻しました」で上書きする
- 再現: 切り替えて表示 → アプリ側で `iptables -I OUTPUT -p udp --dport 56100 -j DROP` → 止める
- 実際の知らせの順: 「点群の送り先を 10.141.0.2 に戻しています…」→（赤）「LiDAR の点群の送り先を 10.141.0.2 に戻せませんでした…」→「ライブを止めました（点群の送り先を 10.141.0.2 に戻しました）」（最後が残る）
- 場所: app.js:2328-2336（結果を見ずに成功の文言）、live.js:522-527（stopAll が stop の成否を返さない）
- 直し方の案: state に `restoreFailed` を入れて、失敗なら赤の文言を残す
- 確度: 再現済み ／ 再現: regress/s3.sh（ui.js）

### R1-005 [中] 戻せなかったあと、元の送り先を忘れる。同じ LiDAR をもう一度表示して止めると確認なしで待機にする
- 再現: R1-004 のあと命令の遮断を解く → 同じ LiDAR を表示（送り先は自分なので確認なし）→ 止める
- 実際: X は「待機」、ロボットは 0 のまま（ログの案内「ロボット側のドライバを起動し直してください」だけが頼り）
- 場所: live.js:233-234（戻す前に active/restore を消す）
- 直し方の案: 戻せなかった restore を SN ごとに残し（live.json にも）、次に表示・止める・終了のときに戻し直す
- 確度: 再現済み ／ 再現: regress/s2.sh

### R1-006 [軽微] 確認の画面を出したままデモを表示すると、デモを止めたあとも古い確認が残り、あとで押すと切り替わる
- 再現: ロボット使用中の LiDAR を押す（確認）→ デモ → 止める → 20 秒後に「切り替える」→ 切り替わる
- 場所: app.js:2397-2403（デモで liveTakeBox を隠さない。同じく startLidar は liveCodeBox を隠さない）
- 直し方の案: デモ・カードを閉じる・一覧の更新で確認を消す
- 確度: 再現済み ／ 再現: regress/s3.sh

### R1-007 [軽微] NIC ごとの探すソケットは、bind に一度失敗すると作り直さない（その NIC からは探さないまま）
- 再現: os.networkInterfaces に先に 10.141.0.99 を出す（bind は EADDRNOTAVAIL）→ 1.5 秒後に実際に付ける → 5 秒後も `ready=false`
- 実機で起きうる例（推定）: Windows で固定 IP を付けた直後（tentative の間は bind できない）、ケーブルを挿した直後
- 場所: live.js:150-155（error を無視して Map に残す。コメントは「次の回に」）
- 直し方の案: error で Map から消す
- 確度: 再現済み（模擬）／ 再現: regress/s4.js

### R1-008 [軽微] 「つないでいます…」の間に配信を見る操作が来ると busy が true のまま残り、カードを閉じてもポートを放さない
- 再現（主プロセスの API で）: `startLidar(Y)` を待たずに `startPeer('nokey')` → p1 は CANCELLED、`busy=true`、16 秒 open なしでもポートは開いたまま
- 画面からは今は起こらない（busy の間は配信のボタンを押せない）。場所: live.js:452-460（startPeer が busy を戻さない）
- 直し方の案: busy を世代番号で持つ（`this.busyGen = g`、`busy = busyGen === gen`）か stopFor で false にする
- 確度: 再現済み（API）／ 再現: regress/s2.sh

### R1-009 [情報] startLidar/startPeer は、失敗（確認が要る・合言葉が要る・見つからない）しても先に今の表示を止める
- 主プロセスでは mode=null・点 0、元の LiDAR は待機。画面は表示中に一覧を隠すので今は起きないが、表示中に一覧を出す変更をすると表示中のまま止まる食い違いになる。確かめてから stopFor する順にしたい（live.js:451-472）

### R1-010 [情報] 点群の箱の CRC32 の範囲は公式の仕様にある
- Livox の MID-360 通信仕様: CRC32 は「時刻＋データ部」（オフセット 28〜末尾）。数えるだけでも入れられる（B28 の残り）。あわせて、bad や送り元違いの箱が来ているときの案内が「ファイアウォール」になるので、`stat.bad`/`stat.other` があれば別の文言に
