- やり方: セッション型の探索的試験（目的を決めた短い探索 6 本）とエラー推測。アプリ版（Electron、xvfb）＋試作ページ（Chromium）。ライブは netns r7（147、3 台: にせ MID-360・LiDAR の PC・受ける PC）

## 見つけた問題

### R7-001 [中] 一度「開けませんでした」が出ると、そのあと別の操作で開いたファイルの「開きました」が出ない（赤い古い知らせが残り続ける）
- 種類: 意図しない挙動 / 対象: 両方
- 再現: 「軌跡を開く」で bag_path_only.mcap（断られる）→ 続けて別の操作で bag_wheel_odom.mcap、さらに「点群を開く」で odom_tum.txt ほか 3 つ、「軌跡として開き直す」
- 期待: 新しい操作の結果（「軌跡 bag_wheel_odom.mcap を開きました…」）が出る
- 実際: 右上はずっと赤の「bag_path_only.mcap を開けませんでした: 軌跡（Odometry / PoseStamped）のメッセージが見つかりません」。開けたのに失敗したように見える（「すべて閉じました」まで消えない）
- 場所: src/app.js:936・969（「開きました」は常に soft）、1922〜1924（soft は誤りを上書きしない）
- 見立て/案: B52 の「まとめて開いたときに誤りを上書きしない」が、別の操作にも効いている。soft は同じ順番待ち（同じ enqueue の束）の中だけにする（新しい enqueue で msgIsError を下ろす）
- 確度: 再現済み（out/s3.log）。スクリプト: work/R7/s3_multi.js

### R7-002 [中] 「画像を保存」の画像に、測った長さ・線の番号・座標の吹き出し・座標軸の名前が入らない
- 種類: 使い勝手 / 対象: 両方
- 再現: scans.pcd → `t` → 距離で廊下の幅を測る（表に 2.397）→「画像を保存」
- 期待: 画面に見えている計測（番号・長さ）が画像にも入る（卒論の図にそのまま使える）
- 実際: 画像は WebGL のキャンバスだけ。線と端の点は入るが、番号の丸・長さの数・座標の吹き出し・x/y の名前・右上の情報は入らない（画面の写真 out/s6_screen.png と保存の中身 out/s6_saved.png を比較）
- 場所: src/app.js:2024〜（renderer.domElement.toBlob）。番号は DOM（m.tag）、吹き出しは #pickInfo
- 案: 保存時に 2D キャンバスへ重ねて描く（番号・長さ・吹き出し・凡例）。少なくとも「計測の数は入りません」と知らせる
- 確度: 再現済み。スクリプト: work/R7/s6_shotcontent.js

### R7-003 [中] 合言葉を全角数字（日本語入力のまま）で入れると「合言葉は 4 桁の数字です」と断られる
- 種類: 使い勝手・文言 / 対象: アプリ版（判定は両方）
- 再現: 受ける PC で配信を「表示」→ 合言葉の欄に「２６０９」→ Enter
- 期待: 半角に直してつなぐ（または「半角で」と案内）
- 実際: 赤で「合言葉は 4 桁の数字です」（4 桁の数字を入れているのに）。半角の 2609 ではつながる
- 場所: src/app.js:2323（/^\d{4}$/ は半角だけ）
- 案: value.normalize('NFKC') してから判定。欄に `ime-mode`/`inputmode` だけでは Windows の IME は切れない
- 確度: 再現済み（out/live/recv.log）。スクリプト: work/R7/live/run.sh

### R7-004 [中] 平らな面を上から選ぶと、クリックした所ではなく、カメラ寄りに最大 5 px 分ずれた点が選ばれる（全体表示で約 30 cm）
- 種類: バグ（精度）/ 対象: 両方
- 再現: scans.pcd（自動で水平補正）→ `t` → 座標を入れ、truth.json の floor_point_M（廊下の中央の床）の画面位置をクリック
- 期待: クリックした画素の真下の点（ずれは 1 画素 ≈ 7 cm 程度）
- 実際: 選ばれた点は廊下の中央から 0.296 m（y の +、カメラのある側）。許容の円錐（5 px = 約 37 cm）の中で「カメラに一番近い点」を選ぶので、床・平らな面ではいつも円錐の縁（カメラ寄り）が選ばれる
- 場所: src/worker.js pickIn（tt が最小の点）、src/app.js:1471〜1473（tolPx）
- 案: 最初に当たった面の厚み（bestT + セル程度）の中で、光線に一番近い点を選ぶ
- 確度: 再現済み（out/s1.log の pick leveled: Y 0.296）。スクリプト: work/R7/s1_fastlio.js
