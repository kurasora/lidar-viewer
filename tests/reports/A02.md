### A02-001 [中] OBJ / OFF の頂点色: 0〜1 と 0〜255 の判定を頂点ごとにするため、暗い頂点が明るくなり、1 をわずかに超える頂点は黒くなる
- 種類: バグ（色の誤り）
- 対象: 両方
- 再現手順:
  1. `$W/regress/data/obj/vc255.obj`（`v x y z r g b` を 0〜255 の整数で書いた OBJ。箱 A は (200,30,30)、箱 B はほぼ黒の (1,1,1)、2 頂点だけ (0,1,0)）を開く
  2. `$W/regress/data/obj/vc_over1.obj`（0〜1 の小数。箱 A の頂点が (1.0000001, 0, 0)）を開く
  3. `$W/regress/data/off/coff255.off`（COFF・色 0〜255、暗い頂点を含む）を開く
- 期待される結果: ファイル全体で 0〜1 か 0〜255 かを決める。vc255 の箱 B はほぼ黒、vc_over1 の箱 A は赤（255,0,0）
- 実際の結果: vc255 の箱 B の平均色 (191,255,191)（ほぼ黒の頂点が白・緑に化ける）。vc_over1 の箱 A は (1,0,0)＝黒。coff255 も箱 B が (191,255,191)
- 証拠: `$W/regress/out/node1.jsonl`（obj_vc255・obj_vc_over1・off_coff255）
- 場所: `src/io/formats/mesh.js:41`（OBJ）、`mesh.js:131`（OFF）
- 原因の見立て: `const sc = (v[3] <= 1 && v[4] <= 1 && v[5] <= 1) ? 255 : 1` を頂点ごとに判定。0〜255 のファイルの暗い頂点（各成分 ≤1）だけが 255 倍される。0〜1 のファイルで 1 をわずかに超える値（丸め誤差・HDR）があると、その頂点だけ 0〜255 とみなされ、さらに `Uint8Array` に入れるため 1.0000001 → 1 になる（0〜255 を超える値は切り詰めでなく折り返し）
- 直し方の案: 頂点をすべて読んでから「最大値が 1.0 を（少し余裕を持って、例 1.001）超えるか」で一度だけ倍率を決め、値は 0〜255 に丸めて詰める（`Math.min(255, Math.max(0, Math.round(...)))`）
- 確度: 再現済み（Node。画面での確認は下の「画面での確認」）
- 再現スクリプト: `$W/regress/node_probe.mjs 'obj_vc|off_coff'`

### A02-003 [中] OBJ / glTF のテクスチャ（map_Kd・baseColorTexture）を無視し、点がすべて白／灰色になる。知らせもない
- 種類: 意図しない挙動（色の誤り）・使い勝手
- 対象: 両方
- 再現手順: `$W/regress/data/obj/tex/t.obj` + `t.mtl`（`Kd 1 1 1`、`map_Kd tex.png`）+ `tex.png`（左の画素が赤、右が青。箱 A は赤、箱 B は青の UV）を一緒に選ぶ。glTF は `gltf/texture.gltf`（baseColorTexture）
