# A11 計算と数値の正しさ 報告

（作業中。見つけたものから順に書き足しています）

## 試験の計画

### 範囲
画面に出る数値と、形を変える計算の正しさ。src/worker.js（間引き・統計・選択の索引・水平補正の解析）、src/app.js の計算部分（座標・距離・範囲・ヒストグラム・色の範囲・天井・軌跡・ライブ表示）、読み込み時の座標変換（Sink のグローバルシフト、E57 pose、PTX 行列、IFC/STEP、GeoTIFF、LAS scale/offset、PLY/PCD の double）、live.js の点の変換。

### 正解の作り方（オラクル）
- 合成データ（numpy で作る）: 真の床の傾き・向き・床の高さ・天井の高さ・点の間隔・範囲が分かっている点群を作り、アプリの出力と比べる
- 独立計算: numpy / scipy（KD 木で最近傍距離の中央値、パーセンタイル、範囲、四元数→行列は scipy.spatial.transform.Rotation）
- CloudCompare（PTX・E57 の変換の比較）、laspy / pye57 / plyfile / ifcopenshell / tifffile で書いた既知のファイル
- Livox SDK2 の公式資料・livox_ros_driver2 の変換式（Web で確認）
- 変成関係（metamorphic）: 既知の回転を掛けた点群 → 水平補正の結果が逆回転になる／大きな平行移動を足しても距離・相対座標が変わらない（1 mm 以内）

### 技法
同値分割・境界値分析（BIG=1e4、Float32 の桁、1.8 m 規則、0.95/0.15 の角度しきい値、Map の 2^24 上限）、差分試験（オラクルとの比較）、変成試験、無作為化試験（乱数の姿勢・傾きで繰り返す）、静的解析（コードを読んで疑わしい所を洗い出し、再現で確かめる）

### 進め方（道具）
- Node で worker.js をそのまま動かす土台（`$W/lib/wk.mjs`: self.onmessage を直接呼ぶ）→ 読み込み・pick・analyze を速く大量に試す
- Chromium（Playwright、dist/index.html）で画面の値（座標の吹き出し・情報の範囲・ヒストグラムの目盛り・天井・軌跡）を読む
- Electron はライブの確認だけ（netns a11）

### A11-007 [重大] 床の下に別の階の床が少し写っていると、それを「床」とみなし、既定の「天井を隠す」で主の階がまるごと消える（91% の点が非表示）
