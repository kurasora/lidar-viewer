### R16-001 [軽微] アプリ版で「ファイル」のカードの下端に横のスクロールバーが出る（R13-001 の続き）
- 種類: バグ（見た目）  対象: アプリ版（Electron。headless の Chromium はスクロールバーを描かないので R13 では「切れる」とだけ見えた）
- 再現: Electron 900×600 でファイルを 30 個開き「ファイル」のカードを出す（$W/rg/A06/regress/scroll_slider.js）。
- 期待: カプセル形の縦のスクロールバーだけ。実際: カードの下端（y≈497、x 22〜297）に横のスクロールバーのつまみが出て、横にも少し動く。
- 証拠: $W/rg/A06/shots/scroll_d1/02_scrollbar_dragged.png
- 原因の見立て: R13-001 と同じ（.popsec の grid の列が最小内容幅まで広がり、#pop の中身が 14px 横にはみ出す）。#pop が overflow:auto なので横のスクロールバーになる。
- 直し方の案: R13-001 の直し（`grid-template-columns: minmax(0,1fr)`、拡張子の折り返し）に加え、#pop に `overflow-x: hidden`。
- 確度: 再現済み

### R16-002 [軽微] 強制カラー（Windows のハイコントラスト）で、座標・距離の吹き出しの「選んでいるもの」が区別できず、点の印が黒くなって 3D の上で見えにくい
- 種類: 使い勝手（アクセシビリティ）  対象: 両方（forced-colors: active のとき）
- 再現: Chromium を forcedColors:'active' で開き、点群を開いて座標を 3 点・距離を 1 本取る（$W/rg/A06/regress/x3_newcards.js の fc / d2fc）。
- 期待: 選んでいる吹き出し（通常は枠が強調色 rgb(126,166,255)）が分かる。点の位置の丸が見える。
- 実際: 吹き出しの枠がすべて白 1px（選んだ #3 もほかと同じ）。x/y/z の色分けも消える（これは仕様上やむを得ない）。吹き出しの根元の丸（.pc-dot）が黒く塗られ、暗い 3D の背景の上でほとんど見えない。
- 証拠: $W/rg/A06/shots/x3/cmp_pins_d1_fc.png（上: 通常、下: 強制カラー）、fc_03_pins_measure.png
- 原因の見立て: 強制カラーで background-color が Canvas（黒）、border-color が CanvasText に置き換わる。選択の印が色だけで表されている。
- 直し方の案: `@media (forced-colors: active)` で .sel の枠を `Highlight` 色・2px に、.pc-dot / .mc-dot に `forced-color-adjust: none`（または背景を `CanvasText`）。
- 確度: 再現済み（Chromium のエミュレーション。Windows の実機のハイコントラストで要確認）
